# Разбор проекта и этапы выпуска — 27.10.2026

## Основа обновления

Работа продолжается от актуальной ветки `main`, коммит `a1af07e2db3447db8869ed05ad6ab6db95b198fc`. В ней уже есть удаление демонстрационных входов, вымышленных отзывов и подставных медиа, рабочая установка без образцов и миграция MySQL 5.7. Эти изменения сохраняются; приложенный архив используется как источник прежней версии и ресурсов, а не для отката репозитория.

Отдельно сопоставлена ветка `release/production-20261027` (`d9fbbd8065f1b626b36f22fe0d50926b000b0ea5`). Её миграция отличается от `main`: она удаляла служебную колонку отзывов и очищала содержимое исходных упражнений. Актуальное обновление учитывает обе схемы. Повторно выполнять SQL из прежней ветки не нужно.

Стек: PHP 8.1+, PDO, MySQL 5.7, JavaScript ES modules, локальные CSS, шрифты и графические ресурсы, Apache/shared hosting. Сборка Node на сервере не требуется. Сервер проверяет сессию, CSRF и права на пациента и медиа.

## Этапы

1. Рабочий режим: проверить уже внесённое удаление демо-механик, закрыть оставшиеся пути доступа к исходным служебным аккаунтам и материалам, уточнить миграцию существующей БД.
2. Статичные персонажи: перегенерировать человека с детскими пропорциями, ориентир роста 100–120 см; заменить рендер «Звёздного дитя» статичным `companion.webp` по приложенному изображению и убрать любые анимации в этом блоке.
3. Визор: перенести отдельные исходные слои Figma `48:331` и пропорции 1672 × 941. Показатели и переходы остаются связанными с данными текущего пациента; на узком экране сохраняется доступ ко всем приборам и действиям.
4. Выпуск: подготовить архив для загрузки поверх действующего сайта, отдельный SQL для существующей БД MySQL 5.7 и инструкцию. Сначала упаковать, затем выполнить только базовые проверки синтаксиса.

Изменения каждого завершённого этапа сохраняются в GitHub проекта.

## Выявлено при повторном разборе

- В `main` демонстрационные входы и подставные видео уже убраны; прежняя документация при этом всё ещё обещала анимацию персонажа и ссылалась на более раннюю исходную ветку. Это не соответствует текущему заданию о статике.
- При обновлении с ранее применённым SQL ветки `release/production-20261027` отсутствовала `testimonials.is_demo`, которую использует текущий API. Миграция теперь восстанавливает её только при отсутствии. Это служебный признак архивного содержимого, а не переключатель демо-режима.
- Исходные упражнения после старой миграции могли иметь пустые описание и шаги. Их распознавание дополнено точной комбинацией исходной даты, автора, названия, категории, уровня и других признаков при отсутствии настоящего видео. Изменённые рабочие материалы не выбираются по одному имени или числовому ID.
- В переданном дампе единственный исходный администратор — служебный аккаунт. Перед миграцией владелец должен создать отдельный настоящий аккаунт администратора с собственным паролем. Общий пароль не входит ни в SQL, ни в клиентский JavaScript.
- Загрузка архива поверх не удаляет отсутствующие в новой версии файлы. Для них предусмотрены запреты прямого доступа, инструмент очистки по контрольным суммам и ручной список известных устаревших путей. Рабочая конфигурация и пользовательское хранилище сохраняются.
- Исходный `cockpitDashboard` использовал другой HUD и интерактивную 3D-планету. Целевой макет использует статичный зуб, собственную рамку, шкалу топлива, кольцо XP и другое расположение элементов.

## Решения по данным и графике

Распознанные служебные аккаунты и материалы архивируются адресно. Реальные аккаунты, клиническая история, загрузки и настройки владельца не очищаются. Общий пароль исходных служебных аккаунтов аннулируется, их восстановление по прежним ссылкам закрывается. Изменённое упражнение с оставшимся подставным видеопутём становится черновиком до добавления настоящего видео.

Визор собирается из отдельных локальных ресурсов Figma. Полный скриншот с запечёнными числами не используется как интерфейс. Текст «Текст кнопки» заменяется действующим переходом. Числа, название назначения, статус и команда читаются из текущего кабинета.

Для персонажей используются статичные растровые изображения. Рендер «Звёздного дитя», обработчик приветствия и кнопка запуска анимации исключаются из этого блока. Голографический человек и персонаж по приложенному референсу сохраняют разные назначения.

## Границы проверки

По заданию заказчика автоматические проверки запускаются только после упаковки и ограничиваются базовым синтаксисом. Полный регресс, нагрузочное тестирование и выполнение миграции на рабочем сервере не входят в этот выпуск. Доступ к рабочему серверу и БД не предоставлен. Секреты, исходный SQL-дамп и материалы пациентов в GitHub не публикуются.
