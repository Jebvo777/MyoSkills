# MyoSkills

PHP 8.2+ и PDO MySQL, MySQL 5.7+/MariaDB 10.4+, обычный Apache shared-хостинг. Без Composer, Node.js, Redis, WebSocket и сборки в production. Приложение работает в подпапке `/mio`; запросы API используют `api.php?action=...`, поэтому mod_rewrite не требуется.

Этапы реализации:
1. Сервер, схема данных, сессии, разграничение прав, установка.
2. Лендинг, графика, галактика и миссии пациента.
3. Команда врачей, направления, фотопротокол, переписка и администрирование.
4. Комплексная проверка сценариев и упаковка для установки.

## Доступ

Пациент получает свои данные. Врачи получают данные активных пациентов своей команды. Специалист, получивший направление, подтверждает факт приёма, после чего появляется доступ к истории. Только миотерапевт назначает упражнения и проверяет выполнение. Ортодонт и миотерапевт добавляют фотопротокол. Администратор управляет пользователями, верификацией документов и библиотекой контента.

Медицинские файлы находятся за пределами публичного API выдачи файлов: `storage` закрыт через `.htaccess`, `media.php` каждый раз проверяет сессию и права. Запись с камеры доступна при поддержке браузера и HTTPS. Загрузка готового видео работает отдельно.

Авторство загрузки не сохраняет доступ к файлу пациента после выхода специалиста из активной команды или отмены верификации. Собственные квалификационные документы остаются доступны специалисту. Смена или восстановление пароля прекращает остальные сессии через проверку отпечатка текущего пароля.

Сохранение контента сначала проверяет всю форму, затем записывает её одной транзакцией. Обновления назначений используют блокировку строки пациента, чтобы врачи не создавали дубли при одновременном сохранении.

## Прогресс

Назначения могут охватывать несколько планет. Сложность определяется назначениями миотерапевта. Выполнение отмечается в дневнике. Награды за один навык ограничены одним начислением каждого вида в сутки. Проверка одного видео повторно не начисляет опыт. Игровой опыт и фотопротокол представлены отдельно.

## Уведомления

Встроенные уведомления сохраняются в MySQL. Email подключается настройкой `mail.enabled` и транспортом PHP mail. СМС и MAX требуют внешнего провайдера, ключей и оплаты; интерфейс не заявляет отправку по неподключённым каналам. Напоминания о пропущенных занятиях запускаются скриптом cron.

База тестовых данных содержит вымышленные имена и демонстрационные материалы. Видео в комплекте показывает интерфейс и не служит медицинской инструкцией. Врач заменяет его своим образцом в библиотеке упражнений.

## Расширенный выпуск

api_extra.php содержит приглашения, редактирование плана лечения, видимость дипломов, отзывы и публичные материалы. Принятие приглашения проверяет почту владельца, срок кода и верификацию врача. Направления врачу вне сервиса записываются без создания фиктивного аккаунта и без доступа к данным пациента.

visit_files связывает материалы с конкретным приёмом. Документы врача доступны клинической команде; фотографии — пациенту. asset.php выдаёт только публичные материалы сайта и явно опубликованные дипломы действующего верифицированного врача. Медицинские файлы пациента через него не выдаются.

WebGL использует локальные GLSL-шейдеры без CDN. Планеты освещаются в реальном времени; ракета следует к выбранной планете. Частота кадров ограничена, сцена останавливается вне экрана и в скрытой вкладке. При уменьшении анимации она статична, при отсутствии WebGL остаются иллюстрации. Модель челюсти построена из CSS 3D-элементов и не прогнозирует исход лечения.

upgrade_20261012.sql обновляет предыдущую схему без удаления записей. Для новой базы используют schema.sql; seed.sql импортируют только в пустую установленную базу.
