# Установка и обновление MyoSkills поверх существующего сайта

Выпуск от 27.10.2026, PHP 8.1+ и MySQL 5.7.

**Архив предназначен для замены кода поверх существующего сайта. Рабочие `config.local.php`, `storage/files` и `storage/logs` сохраняются на месте. Удалять всю папку сайта или импортировать исходный дамп вместо миграции не нужно.**

## Состав архива

В корне архива `OVERLAY.zip` находятся файлы приложения, включая `index.php`, `api.php`, `.htaccess`, `assets/`, `app/`, `database/` и `docs/`. Распакуйте архив **в существующий корень сайта**: если сайт расположен в `/mio`, новый файл должен оказаться в `/mio/index.php`. Внешней папки `MyoSkills` в архиве нет. Инструкция находится внутри в `docs/DEPLOYMENT.md` и предоставляется отдельно как `INSTALL-UPDATE.md`.

Основные SQL-файлы находятся внутри проекта:

| Файл | Когда использовать |
|---|---|
| `database/upgrade_20261027_production.sql` | Обновление существующей БД |
| `database/install.sql` | Новая установка в пустую БД |
| `database/create_admin_from_account.sql` | Назначение администратора из нового отдельного аккаунта без SSH |
| `database/bootstrap.sql` | Категории и базовое содержимое; уже включён в установку и обновление |

Для обновления достаточно одного файла `upgrade_20261027_production.sql`; отдельно запускать прежнюю миграцию или `bootstrap.sql` не требуется. Если SQL приложен к выпуску отдельным файлом, используйте ту же миграцию только один раз. Повторный импорт допустим, но не нужен для обычной установки.

В публичный репозиторий и архив приложения не входят пароль БД, действующий `config.local.php`, пользовательские загрузки и исходный SQL-дамп с аккаунтами. Настройки и файлы переносятся с работающего сайта. Приложенный ранее дамп использовался для изучения структуры; его не нужно импортировать поверх актуальной базы.

## 1. Подготовьте резервную копию

До замены кода сохраните за пределами публичного каталога сайта:

1. Свежий экспорт всей действующей БД из phpMyAdmin.
2. Действующий `config.local.php`.
3. Всю папку `storage/files` с загруженными видео, фото и документами.
4. При необходимости — `storage/logs` и копию старого кода для возврата к прежней версии.

Убедитесь, что копия файлов действительно сохранена, а не содержит только пустые каталоги. Для последующего отката нужны согласованные копии БД и файлов. Архив приложения не заменяет резервную копию пользовательских материалов.

## 2. Создайте настоящего администратора до миграции

В предоставленном снимке БД единственный администратор относится к исходным служебным аккаунтам. Миграция отключит этот аккаунт вместе с другими распознанными образцами. Сначала создайте отдельный аккаунт владельца с собственным паролем.

### Через phpMyAdmin, без SSH

1. Пока прежний сайт работает, зарегистрируйте через обычную форму **новый отдельный аккаунт пациента** с действующей почтой владельца и собственным паролем. Не используйте учётную запись действующего пациента или лечащего врача. Не подключайте к новому аккаунту врачей, упражнения или файлы.
2. Откройте `database/create_admin_from_account.sql` в текстовом редакторе. Найдите строку с пустым адресом и впишите почту созданного аккаунта:

   ```sql
   SET @myo_admin_email = 'owner@your-domain.ru';
   ```

   Замените пример своим адресом. Остальные SQL-поля менять не нужно.
3. В phpMyAdmin выберите **существующую БД MyoSkills** и импортируйте изменённый файл целиком.
4. Последний запрос должен вернуть `Administrator ready. Sign out and sign in again.` Выйдите из аккаунта на сайте и войдите заново тем же паролем.

Скрипт не зависит от новых полей `archived_at` и подходит для исходной структуры до миграции. Он не меняет пароль, не создаёт общий пароль и не повышает аккаунт с клинической историей, командой, файлами, сообщениями или приглашениями. Если адрес оставлен пустым либо аккаунт не подходит, изменения не выполняются. Зарегистрируйте отдельный новый аккаунт и повторите процедуру с его адресом.

### Через SSH

Из каталога проекта выполните:

```bash
php tools/create_admin.php owner@your-domain.ru
```

Укажите свою почту. Скрипт запросит новый пароль и его повтор; существующий аккаунт не перезаписывается. Минимальная длина пароля администратора — 12 символов.

Если PHP доступен на вашем компьютере, но SSH хостинга отсутствует, режим `--sql` позволяет создать приватный INSERT для phpMyAdmin без подключения к БД. Например, из локальной папки проекта:

```bash
php tools/create_admin.php owner@your-domain.ru --sql > admin-private.sql
```

Импортируйте полученный файл в выбранную БД и удалите его после использования. Не загружайте его в публичный каталог и не добавляйте в Git: он содержит хеш учётных данных. Обычный вариант через регистрацию и `create_admin_from_account.sql` не требует локального PHP.

## 3. Обновите существующую БД

На время обновления остановите новые записи и загрузки через режим обслуживания хостинга. Повторно сохраните актуальную резервную копию, если после первого экспорта появились данные.

В phpMyAdmin выберите существующую БД и импортируйте:

```text
database/upgrade_20261027_production.sql
```

Миграция рассчитана на MySQL 5.7, не создаёт пользователей MySQL и не требует новой базы. Для неё нужны обычные права изменения таблиц и создания временных таблиц в выбранной БД. Процедуры и возможности MySQL 8 не используются.

Скрипт добавляет поля архива, сохраняет реальные аккаунты и клинические записи, а распознанные исходные записи делает недоступными. В переданном снимке этим условиям соответствуют 8 исходных аккаунтов, 12 исходных упражнений и 3 исходных файла. Выбор основан на точных признаках записи, а не на её числовом ID. Текущие изменения рабочей БД оцениваются по тем же условиям. Для распознанных служебных аккаунтов также аннулируется старый общий пароль; пароль вашего настоящего аккаунта не меняется.

Назначения архивных упражнений приостанавливаются. Изменённое владельцем упражнение, у которого остался исходный подставной путь к ролику, становится черновиком до загрузки настоящего видео. Реальные загруженные видео и изменённое содержимое не удаляются. Настройки, которые владелец уже отредактировал, сохраняются.

В конце импорта выводятся версия и число действующих администраторов. Значение `active_administrators` должно быть больше нуля перед возобновлением работы. Если администратора ещё нет, создайте его описанным выше способом.

Миграцию можно повторить. Изменения структуры MySQL фиксируются неявно: для отката всей операции используется резервная копия, а не только команда `ROLLBACK`.

Если уже применялось обновление из ветки `release/production-20261027`, используйте этот же актуальный SQL. Он учитывает удалённую той версией служебную колонку `testimonials.is_demo` и уже отключённые исходные упражнения. Колонка нужна только для изоляции старых архивных отзывов; демонстрационного режима в приложении нет. Записи, физически удалённые ранее выполненным скриптом, этот выпуск восстановить не может. Повторно запускать старый `upgrade_20261027_mysql57.sql` из той ветки не нужно.

## 4. Замените код поверх существующего каталога

После сохранения резервной копии и успешного импорта SQL распакуйте `OVERLAY.zip` в прежний каталог сайта и разрешите замену совпадающих файлов. Например, новый `index.php` должен заменить прежний `/mio/index.php`. Не создавайте дополнительную вложенную папку.

В архиве нет `config.local.php` и содержимого действующего хранилища. При обычной загрузке поверх они остаются на месте. Не включайте режим синхронизации с удалением отсутствующих в архиве файлов: он может удалить пользовательские загрузки. Загрузите новые `.htaccess`, включая правила закрытия доступа к служебным каталогам.

Загрузка поверх сама по себе не удаляет файлы, исключённые из новой версии. Новые правила `.htaccess` закрывают прямой доступ к каталогу `demo` и прежнему `assets/demo-mission.mp4` сразу после замены. Для удаления исходных образцов при наличии SSH выполните из каталога проекта:

```bash
php tools/cleanup_legacy.php
php tools/cleanup_legacy.php --apply
```

Первая команда только показывает кандидатов. Вторая удаляет известные исходные файлы при совпадении их контрольной суммы с исходным комплектом. Изменённые файлы пропускаются; конфигурация и содержимое `storage/files` не являются кандидатами. Не добавляйте в список очистки неизвестные пути.

Без SSH после резервного копирования можно удалить через файловый менеджер только перечисленные устаревшие исходные файлы, если они остались:

```text
demo/demo-photo-before.webp
demo/demo-photo-after.webp
demo/demo-video.mp4
assets/demo-mission.mp4
database/install_with_demo.sql
database/seed.sql
tools/build_seed.py
tests/router.php
tests/smoke.py
tests/ui.mjs
tests/fixtures/schema-v1.sql
```

Эти пути относятся к прежним встроенным образцам и сценариям разработки. Папку `storage` и файлы внутри `storage/files` не очищайте. Если на сервере путь из списка был заменён вашей собственной разработкой, сначала сохраните его отдельно и проверьте назначение. Устаревший `database/upgrade_20261027_mysql57.sql`, если он остался после другой ветки выпуска, также следует убрать из каталога миграций, чтобы не запускать его вместо актуального скрипта. Новую заглушку `demo/.htaccess` сохраняйте: она закрывает каталог, в том числе если часть старых файлов осталась.

В `config.local.php` проверьте соответствие расположению сайта:

- `base_path`: `/mio` для адреса вида `https://ваш-домен/mio/`, пустая строка при размещении в корне домена;
- `app_url`: полный действующий HTTPS-адрес без завершающего `/`;
- `db`: прежние рабочие параметры подключения к существующей БД;
- `debug`: `false` для рабочего сайта.

Пароль подключения берётся из сохранённого файла или настроек хостинга. Не заменяйте работающий файл шаблоном с пустым паролем. Если локальной конфигурации раньше не было, создайте её из `config.example.php` и заполните свои значения.

## 5. Настройте хостинг

Требуются PHP 8.1+, `pdo_mysql`, `mbstring`, `fileinfo`, сессии, MySQL 5.7/InnoDB и Apache 2.4. Composer и сборка Node.js не нужны. SQL устанавливается в БД, выбранную в панели; права `CREATE USER` и `CREATE DATABASE` приложению не требуются.

PHP должен иметь право записи в `storage/files` и `storage/logs`. Владелец этих каталогов должен соответствовать пользователю PHP на хостинге. Обычно подходят `0750` или `0755` для каталогов и `0640` или `0644` для файлов; приложение создаёт загрузки с правами `0640`. Не устанавливайте `0777` вместо настройки владельца и группы.

Правила `.htaccess` должны исполняться. Прямой доступ к `app`, `database`, `tools`, `docs`, `storage` и файлам конфигурации закрыт. Если используется сервер, который не читает `.htaccess`, аналогичные запреты нужно задать в его конфигурации до открытия сайта. Медицинские материалы выдаются через `media.php` после проверки прав; публичные материалы — через `asset.php`.

Лимиты приложения по умолчанию: видео 80 МБ, фото 12 МБ, документы 15 МБ. Пределы PHP и веб-сервера должны быть не меньше выбранных лимитов. Для лимита видео 80 МБ подойдут, если это разрешает тариф:

```ini
upload_max_filesize = 80M
post_max_size = 100M
max_execution_time = 120
max_input_time = 120
```

Включите HTTPS. Запись с камеры требует защищённого соединения, поддержки браузера и разрешения пользователя. Готовый файл можно загрузить отдельно. Приложение не перекодирует видео; совместимость конкретного файла зависит от кодека и браузера.

## 6. Наполните рабочую библиотеку

Войдите под настоящим администратором. Загрузите реальные видеообразцы, добавьте описание и шаги упражнений, затем включите их публикацию. Материал без видео, описания и шагов остаётся черновиком.

Врач регистрирует собственный профиль и загружает квалификационные документы; администратор подтверждает профиль. Верифицированный миотерапевт формирует актуальные назначения пациентам. Старые исходные упражнения больше не показываются как действующие; связанные реальные записи истории и загрузки остаются сохранёнными.

Контакты, реквизиты, документы сервиса и необходимые страницы заполняются в админке. Отзывы появляются только после отправки настоящим пользователем и модерации. Пустой список специалистов, отзывов или упражнений не заменяется вымышленными записями.

## Почта и напоминания

Внутренние уведомления сохраняются в БД. Для писем включите `mail.enabled` в локальной конфигурации, задайте разрешённый хостером адрес `mail.from` и настройте доставку PHP `mail()`. Пока канал отключён, восстановление пароля по почте недоступно; интерфейс сообщает об этом.

Для напоминаний добавьте в cron запуск:

```text
php /полный/путь/к/mio/tools/reminders.php
```

Расписание задаётся в панели хостинга. Приложение использует часовой пояс `Europe/Moscow`, но часовой пояс самого cron может отличаться. Скрипт учитывает настройки пользователя, действующие назначения и уже созданное напоминание за день.

## Если установка выполняется с нуля

Для новой пустой БД используйте `database/install.sql`, а не миграцию. Создайте `config.local.php`, импортируйте установку и создайте администратора через CLI либо регистрацию и phpMyAdmin. Далее настройте хранилище, HTTPS и рабочую библиотеку так же, как описано выше.

Не запускайте чистую установку поверх действующего сайта. CLI `tools/install.php` останавливается, если обнаруживает существующие таблицы MyoSkills, и предлагает использовать миграцию.

## Объём проверки выпуска

По заданию заказчика сначала создаётся архив, затем выполняются только базовые проверки синтаксиса. Их фактические результаты указываются в отдельном отчёте выпуска. Этот документ не заявляет запуск миграции на рабочем сервере, доставку писем, проверку камеры или полный регресс приложения. Подробнее: `docs/QA.md` в архиве проекта.
